# Intentional Computing

> **Computing should increase human capability without demanding human attention in exchange.**

Intentional Computing is a philosophy for designing and using technology around **human intention, agency, and ownership**.

It is not a rejection of modern technology.

It is an attempt to answer a question that has become increasingly important as computers, networks, and artificial intelligence have become more powerful:

> **What should our relationship with technology actually be?**

The answer proposed here is simple:

> Technology should serve the person using it.

The computer should become more capable without becoming more controlling.

The internet should become more useful without becoming more consuming.

AI should reduce complexity without creating dependency.

Software should become more powerful without becoming more intrusive.

And the user should remain free to stop.

---

# 1. The Original Promise of Personal Computing

Personal computing began with an unusually powerful idea:

> A computer belongs to the person using it.

The computer was not necessarily connected to a corporation.

It did not necessarily require an account.

It did not necessarily need permission from a remote service.

Software could be installed.

Files could be copied.

Programs could be modified.

Information could be stored locally.

The machine could be used for whatever the owner wanted.

The computer was a general-purpose tool.

That idea remains valuable.

Modern technology has expanded the capabilities of the computer enormously, but the relationship between person and machine has not always improved alongside that capability.

---

# 2. The Shift From Tool to Environment

A traditional computer application generally had a boundary.

You opened it.

You used it.

You accomplished something.

You closed it.

The modern digital environment increasingly removes those boundaries.

Instead of:

```text id="t0e2cz"
Open
  ↓
Use
  ↓
Complete
  ↓
Close
```

we increasingly encounter:

```text id="z4s0y1"
Open
  ↓
Content
  ↓
Recommendation
  ↓
More content
  ↓
Recommendation
  ↓
Notification
  ↓
More content
  ↓
Another recommendation
  ↓
...
```

The software no longer has a clear stopping point.

The user is no longer simply using the computer.

The computer is attempting to keep the user inside the computer.

This represents a fundamental change in the relationship.

---

# 3. Attention Became a Resource

Human attention is finite.

There are only so many hours in a day.

Only so much information can be processed.

Only so many things can be meaningfully considered.

Technology can either help us manage that limitation or exploit it.

An intentional system treats attention as something to protect.

An engagement-driven system treats attention as something to capture.

This distinction is fundamental.

Consider two possible goals:

```text id="1f4l9u"
SYSTEM A

Help the user find what they need.
        ↓
Task completed.
        ↓
User leaves.
```

and:

```text id="v4xq8n"
SYSTEM B

Keep the user engaged.
        ↓
More content.
        ↓
More engagement.
        ↓
More recommendations.
        ↓
More engagement.
```

Both systems can use sophisticated technology.

Only one treats the user's attention as belonging to the user.

---

# 4. Intentionality

Intentional computing begins with the concept of **intent**.

The user should be able to answer:

> What am I trying to do?

The software should help answer:

> What is the simplest way to accomplish that?

This creates a natural relationship:

```text id="4i6h5f"
INTENT
   ↓
ACTION
   ↓
RESULT
   ↓
COMPLETION
```

The software should not automatically add:

```text id="xj0n0e"
RESULT
   ↓
RECOMMENDATION
   ↓
ENGAGEMENT
   ↓
MORE CONTENT
```

unless the user explicitly wants that.

This distinction may appear small.

It is not.

It determines whether software is organized around the **user's objective** or around the **system's objective**.

---

# 5. Completion Is a Feature

Many modern systems treat continued usage as success.

Intentional Computing treats **completion** as success.

If a person opens a tool to:

* find a file
* edit an image
* research a subject
* write a document
* fix code
* watch a particular video
* play a game

then the ideal outcome is that the task gets completed.

The user does not need to remain in the application afterward.

A successful application may therefore produce less screen time, not more.

That is not failure.

That is success.

---

# 6. Finite Computing

Intentional systems should generally have boundaries.

A finite interface provides:

* a beginning
* a set of available actions
* a visible state
* a result
* an ending

This is particularly important for information systems.

There is always more information available.

That does not mean the user needs to see it.

A useful system may deliberately present:

```text id="1b6v9g"
10 useful results
```

instead of:

```text id="2a1mmy"
10 results
↓
load more
↓
load more
↓
load more
↓
load more
↓
...
```

Finiteness gives the user permission to stop.

---

# 7. Search Instead of Feeds

A feed assumes that the system should decide what comes next.

Search begins with the user.

A feed asks:

> What should we show this person?

Search asks:

> What is this person looking for?

Intentional Computing generally favors the second model.

This does not mean recommendation systems are inherently bad.

Recommendations can be extremely useful.

The difference is who controls the relationship.

Recommendation should assist intent.

It should not manufacture intent.

---

# 8. Curation Instead of Volume

The internet contains an enormous amount of information.

The solution to information overload cannot simply be:

> Show the user more information faster.

A better approach is:

> Help the user see less, but better.

This is where filtering and AI become particularly powerful.

Imagine:

```text id="yd6w6a"
1,000,000 possible items
        ↓
     Filters
        ↓
   AI analysis
        ↓
 User preferences
        ↓
     20 useful items
```

The purpose of the system is not to maximize the number of items presented.

It is to reduce the amount of information the human must personally process.

This is one of the most important applications of AI within Intentional Computing.

---

# 9. AI as Compression

AI can be thought of as a **complexity compression layer**.

The world contains more information than a person can reasonably examine.

AI can help compress that complexity into something understandable.

For example:

```text id="g7qf2e"
Large information space
        ↓
      AI
        ↓
Relevant information
        ↓
Human judgment
```

The human remains responsible for the meaningful decision.

The machine handles the mechanical complexity.

This is preferable to using AI to create another layer of automated stimulation.

---

# 10. AI Should Not Become the Goal

There is a temptation to put AI everywhere simply because it is possible.

That is not intentional computing.

AI is a means.

It should be introduced when it provides meaningful capability.

Good uses include:

* filtering
* classification
* summarization
* transformation
* organization
* search
* automation
* translation
* coding assistance
* accessibility
* analysis

Poor uses include adding AI simply because:

> "There should be AI here."

The question should always be:

> **Does AI make the user's objective easier, clearer, or more powerful?**

If not, it may not belong.

---

# 11. Human Judgment Remains Important

Intentional Computing does not attempt to eliminate human judgment.

Instead, it attempts to preserve it for the things that actually matter.

A useful division is:

```text id="0p7z6q"
MACHINE
- Search
- Classification
- Sorting
- Calculation
- Repetition
- Transformation
- Pattern detection
- Data processing

              ↓

HUMAN
- Intent
- Preference
- Judgment
- Meaning
- Values
- Creativity
- Final decisions
```

The machine handles what machines are good at.

The human handles what humans are good at.

---

# 12. Local Computing Matters

Intentional Computing places significant value on local software.

Local computing provides:

* ownership
* privacy
* resilience
* offline capability
* independence
* predictable behavior
* lower dependency
* long-term preservation

This does not mean everything must run locally.

The internet is extraordinarily useful.

Cloud computing is extraordinarily useful.

Remote services can provide capabilities that would be impractical locally.

The principle is instead:

> **Do not make remote dependency the default when local ownership is practical and valuable.**

---

# 13. The Internet Should Be a Resource

The internet is one of humanity's greatest information resources.

It should remain accessible.

But access does not require immersion.

There is an important difference between:

> Using the internet.

and:

> Living inside an internet platform.

Intentional Computing prefers the first.

The ideal relationship might be:

```text id="w3n7j6"
PERSON
  ↓
INTENT
  ↓
INTERNET
  ↓
USEFUL INFORMATION
  ↓
PERSON
```

Rather than:

```text id="r5y7xz"
PERSON
  ↓
PLATFORM
  ↓
ALGORITHM
  ↓
CONTENT
  ↓
ENGAGEMENT
  ↓
PLATFORM
  ↓
...
```

---

# 14. Ownership

A person's work should remain theirs.

This includes:

* documents
* photographs
* artwork
* code
* music
* configurations
* archives
* research
* personal knowledge
* creative projects

A service may help create or manage those things.

It should not make the person permanently dependent upon the service merely to access them.

This is why open formats and exportability matter.

A useful test is:

> **If this application disappeared tomorrow, could I still use my work?**

The more often the answer is yes, the healthier the architecture.

---

# 15. Software Should Have Boundaries

A useful application should have a clear identity.

It should have a primary purpose.

A pixel editor should primarily help create pixel art.

A video search application should primarily help find videos.

An emulator should primarily emulate a machine.

A personal information system should primarily help manage information.

Software does not become better simply because it contains more features.

Every additional capability introduces:

* complexity
* maintenance
* interface burden
* cognitive load
* potential failure modes

Intentional Computing therefore favors:

> **Deep capability within clear boundaries.**

---

# 16. Simplicity Is Not the Same as Weakness

Intentional Computing does not mean making primitive software.

A system can be extremely sophisticated internally while remaining simple to use.

For example:

```text id="9pk2xj"
                    COMPLEXITY
                       │
                       ▼
                 ┌───────────┐
                 │  MACHINE  │
                 └─────┬─────┘
                       │
                       ▼
                  SIMPLE USER
                    INTERFACE
```

This is desirable.

The machine should absorb complexity whenever doing so provides the user with greater clarity.

The user should not need to understand every internal mechanism to use the system effectively.

---

# 17. Understandability Still Matters

Although users should not need to understand everything internally, the system itself should remain understandable to its developers and maintainers.

This means favoring:

* clear architecture
* explicit behavior
* documented interfaces
* sensible dependencies
* readable code
* stable formats
* predictable configuration
* replaceable components

Software that cannot be understood eventually becomes software that cannot be maintained.

---

# 18. The Importance of Exit

One of the strongest tests of intentional software is the ability to leave.

The user should be able to:

* close the application
* disconnect from the internet
* export their data
* stop using the service
* replace a component
* migrate to another tool

without catastrophic loss.

This produces an important principle:

> **The user should never be trapped by the software.**

---

# 19. Technology Should Strengthen Real Life

Computing is not the purpose of life.

Computers exist within life.

The ideal outcome of good technology is therefore often that the user spends **less time thinking about the technology**.

A successful system might look like:

```text id="8t1vpa"
Technology
    ↓
Useful result
    ↓
Technology disappears
    ↓
Person continues living
```

This is particularly important as AI becomes more capable.

The objective should not be to create increasingly sophisticated digital environments that demand permanent participation.

The objective should be to make the machine increasingly capable of helping and increasingly capable of getting out of the way.

---

# 20. The 1990s Are a Reference Point

The 1990s are useful as a philosophical reference because personal computing had not yet fully developed the modern attention economy.

The technology was dramatically less capable.

But the relationship with the computer often felt more deliberate.

There were:

* applications
* files
* folders
* menus
* utilities
* games
* creative tools
* websites
* forums
* search engines

There were boundaries.

The goal is not to reproduce those limitations.

The goal is to combine:

```text id="r7j3mp"
1990s Personal Computing
          +
Modern Hardware
          +
Modern Software
          +
AI
          +
Modern Internet
          ↓
Intentional Computing
```

Take the best capabilities from both eras.

Leave the worst assumptions behind.

---

# 21. This Is Not Nostalgia

Nostalgia looks backward.

Intentional Computing looks forward.

The question is not:

> How can we make computers work like they did thirty years ago?

The question is:

> What would a better future look like if we retained the strongest qualities of personal computing?

That future can include:

* AI
* powerful graphics
* cloud services
* global networks
* advanced automation
* high-performance hardware
* immersive interfaces
* machine learning

None of these technologies are inherently incompatible with intentionality.

The question is how they are used.

---

# 22. A Different Definition of Progress

Progress is often measured as:

* more features
* more users
* more engagement
* more data
* more automation
* more connectivity
* more screen time

Intentional Computing proposes different measures:

* more capability
* less unnecessary effort
* less cognitive load
* greater ownership
* greater autonomy
* better information
* better tools
* greater longevity
* less unwanted attention
* more time for life

A system that accomplishes more while demanding less from its user is making meaningful progress.

---

# 23. The Personal Computing Environment

Ultimately, Intentional Computing is not just about individual applications.

It is about the environment surrounding the person.

A healthy personal computing environment might look like:

```text id="m4q6c0"
                         PERSON
                           │
                           ▼
                         INTENT
                           │
              ┌────────────┼────────────┐
              │            │            │
              ▼            ▼            ▼
          SOFTWARE       AI        INTERNET
              │            │            │
              └────────────┼────────────┘
                           │
                           ▼
                     USEFUL RESULT
                           │
                           ▼
                      COMPLETION
                           │
                           ▼
                         LIFE
```

Everything points toward the person.

Nothing needs to continuously pull the person back.

---

# 24. Intentional Computing Is a Direction

There is no single perfect implementation.

There is no requirement that every application behave identically.

There is no checklist that automatically makes software intentional.

Instead, Intentional Computing is a direction.

When faced with a design decision, ask:

> Does this give the user more control or less?

> Does this reduce complexity or create more?

> Does this protect attention or consume it?

> Does this preserve ownership or increase dependency?

> Does this help the user finish or encourage them to continue?

> Does this make the computer more useful or simply more present?

These questions are often more important than the choice of programming language or framework.

---

# 25. The Core Relationship

The philosophy can ultimately be reduced to one relationship:

```text id="6m6wqf"
          HUMAN
            │
            │ INTENTION
            ▼
         COMPUTER
            │
            │ CAPABILITY
            ▼
          RESULT
            │
            ▼
           LIFE
```

The computer exists between intention and result.

It should not become the destination.

---

# 26. The Future

The future of computing does not have to mean:

> Everything connected.

> Everything personalized.

> Everything recommended.

> Everything optimized for engagement.

> Everything mediated by a platform.

> Everything requiring an account.

> Everything demanding constant attention.

There is another possible future.

A future where:

* AI handles complexity
* computers become more powerful
* software becomes easier to build
* information becomes easier to filter
* personal data remains personal
* local computing remains viable
* the internet becomes more useful
* interfaces become calmer
* tools become more capable
* people regain control over their digital environment

That future is not less technological.

It is **more intentional**.

---

# 27. The Ultimate Principle

Intentional Computing can ultimately be expressed as a simple hierarchy:

```text id="2qz3w0"
HUMAN
  │
  ▼
INTENT
  │
  ▼
TECHNOLOGY
  │
  ▼
CAPABILITY
  │
  ▼
RESULT
  │
  ▼
LIFE
```

The hierarchy should not be reversed.

Technology should not determine the user's intent.

Platforms should not determine what deserves attention.

Algorithms should not determine what a person values.

AI should not determine what a person wants.

The machine should help execute human intention.

---

# Conclusion

The purpose of Intentional Computing is not to make technology smaller.

It is to make **the human relationship with technology healthier**.

We can build more powerful computers.

We can build better software.

We can build better networks.

We can build extraordinarily capable AI.

We can preserve old systems.

We can create entirely new ones.

But capability should not require surrender.

The future should not require permanent participation.

And progress should not be measured by how long we can keep someone looking at a screen.

The measure should be simpler:

> **Did the technology help the person do what they wanted to do?**

If yes, it succeeded.

And once the task is complete:

> **Let the person walk away.**
